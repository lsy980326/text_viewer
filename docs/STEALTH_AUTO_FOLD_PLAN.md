# NOVELIER 몰래보기 상단 이동·자동 접기 계획

> 상태: 자동 접기 구현 전 승인 계획 (`ORCH-20260725-024` 2차 UI 정정 반영)  
> 기준일: 2026-07-25  
> 작업 기준: `ORCH-20260725-022`, `ORCH-20260725-024`

최신 정정에 따라 창 이동 영역은 이번 수정 대상이 아니며, 현재 전용
`이동` 핸들을 유지한다. 소설 본문의 브라우저 선택·선택문 드래그는
창 이동과 별개로 차단한다. 상단 배경 농도 슬라이더와 퍼센트는
유지하되 배경이 투명해질수록 함께 희미해지고 hover·focus에서 다시
드러난다. 아래의 상단 빈 영역 확대는 자동 접기와 함께 검토할 후속
범위다.

## 1. 결론

다음 방향을 기본안으로 한다.

1. 몰래보기 상단 바의 **빈 영역 전체**를 창 이동 영역으로 만든다.
2. 농도 슬라이더와 자동 접기·최소화·복원 버튼은 창 이동에서
   명시적으로 제외한다.
3. `자동 숨김`이라는 이름 대신 실제 동작에 맞는 **자동 접기**를 쓴다.
   모든 자동 동작은 완전 숨김이 아니라 운영체제의 안전한 최소화다.
4. 첫 구현은 **포커스 이탈 자동 접기** 하나만 제공한다.
5. 자동 접기는 기본 꺼짐, 몰래보기 세션 전용이며 앱 재시작이나 일반
   PC 보기 복원 시 자동으로 해제한다.
6. 카메라·마이크·사람 인식은 사용하지 않는다. 갑자기 사람이 나타나는
   상황 자체를 센서 없이 신뢰성 있게 감지할 방법은 없으므로,
   `Cmd/Ctrl+Shift+H` 즉시 접기를 항상 보조 경로로 유지한다.

## 2. 요청 해석

상단 바의 의도는 아래와 같다.

```text
┌──────────────────────────────────────────────────────────┐
│ ⋮ 이동 가능한 빈 영역 │ 배경 농도 │ 자동 접기 │ − │ 복원 │
└──────────────────────────────────────────────────────────┘
  └──── 창 이동 ───────┘   └──────── 조작 전용 / 이동 금지 ────────┘
```

- 그립, `이동` 문구, 컨트롤 사이의 빈 배경과 상단 바 여백을 잡으면
  창이 이동한다.
- 농도 슬라이더는 배경 alpha를 따르며 희미해지고, hover·focus에서
  드러나지만 창 좌표는 바꾸지 않는다.
- 자동 접기·최소화·복원 버튼을 누를 때는 해당 버튼만 동작한다.
- 본문, 모바일 도구막대와 팝오버를 끌어도 창이 이동하지 않으며
  본문 자체의 텍스트 선택·선택문 드래그도 발생하지 않는다.
- 일반 PC 타이틀바의 기존 창 이동 동작은 유지한다.

상단 바에 조작 요소가 있으므로 문자 그대로 모든 픽셀을 창 이동으로
만들 수는 없다. **상단 바 전체 배경은 이동, 실제 컨트롤은 이동 금지**가
충돌 없는 완료 기준이다.

## 3. 상단 이동 영역 수정

### DOM 계약

- `.stealth-quick-controls` 전체를
  `data-tauri-drag-region="deep"`으로 지정한다.
- `.stealth-drag-handle`도 `deep`을 유지해 그립의 SVG와 문구 모두
  드래그를 시작하게 한다.
- `label`, `input`, `button`에는
  `data-tauri-drag-region="false"`를 명시해 이후 마크업이 바뀌어도
  컨트롤이 창 이동을 시작하지 않게 한다.
- 전체 툴바의 클릭 핸들러로 `startDragging()`을 중복 호출하지 않는다.
  Tauri의 네이티브 드래그 영역 계약을 한 경로로만 사용한다.

### 레이아웃 계약

- 고정 `78px`인 이동 핸들을 `flex: 1`로 바꿔 남는 상단 공간을 모두
  사용한다.
- `430px` 창의 목표 이동 영역은 `100×44px` 이상이고, 방어적으로
  검사하는 `360px` 폭에서도 최소 `60×44px`를 유지한다.
- 농도 컨트롤은 남은 이동 영역과 버튼을 침범하지 않는 폭을 유지하고,
  휴지 상태 `4%` 하한과 hover·focus `78%` 하한을 적용한다.
- 툴바 전체는 `430px` 창 안에서 가로 스크롤이나 겹침이 없어야 한다.
- 배경에는 `grab`, 컨트롤에는 `pointer` 또는 각 입력 고유 커서를
  사용하고 드래그 중에만 `grabbing`을 표시한다.

### 이동 승인 기준

- macOS와 Windows에서 그립 아이콘, `이동` 문구, 컨트롤 사이의 빈
  배경을 각각 시작점으로 드래그했을 때 창 좌표가 변한다.
- 슬라이더 thumb/track, 자동 접기, 최소화, 복원 버튼에서 드래그를
  시작하면 창 좌표가 변하지 않는다.
- 투명도 `0%`, `28%`, `82%`, 밝음·세피아·어두움 테마에서 동일하다.
- 화면 가장자리로 이동해도 다음 실행 또는 일반 PC 복원 시 창이
  화면 밖에 갇히지 않는다.
- 상단 빈 영역을 더블클릭해도 몰래보기 창이 갑자기 최대화되지 않는다.
  Tauri 기본 더블클릭 동작이 발생하면 몰래보기 세션에서만 이를
  차단하거나 네이티브 `maximizable` 상태를 snapshot과 함께 관리한다.

## 4. 자동 접기 후보 비교

| 후보 | 장점 | 오작동 위험 | 결정 |
| --- | --- | --- | --- |
| 네이티브 창 포커스 이탈 | 별도 권한이 없고 macOS·Windows 동작이 명확함 | 다른 앱이나 메뉴를 의도적으로 누를 때도 접힘 | **1차 구현** |
| 일정 시간 입력 없음 | 자리를 비운 경우 보호 | 읽기만 하고 조작하지 않아도 접힐 수 있음 | 2차 선택 기능 |
| 마우스가 창 밖으로 나감 | 빠르게 반응 | 스크롤·멀티모니터 사용에서 매우 자주 오작동 | 제외 |
| 화면 모서리 제스처 | 수동 비상 동작으로 빠름 | 전역 포인터 감시와 사용자 학습 필요 | 후속 검토 |
| 화면 잠금·절전 | 자리를 비운 상황에서 안전 | 갑작스러운 사람 접근에는 반응하지 않음 | 후속 네이티브 보강 |
| 카메라·마이크 사람 감지 | 이론상 자동 반응 | 민감한 권한, 오탐, 배터리, 신뢰 문제 | **제외** |

### 추천 1차 동작

- 몰래보기에서 사용자가 `자동 접기`를 직접 켠다.
- 네이티브 창이 포커스를 잃으면 `300ms` 안정화 시간 후 한 번만
  최소화한다.
- 안정화 시간 안에 다시 포커스를 얻으면 예약한 최소화를 취소한다.
- 최소화 직전 본문 위에 내용이 없는 중립 가림막을 렌더링하고 다음
  animation frame에서 최소화한다. 작업 표시줄 미리보기나 짧은 창
  애니메이션에 본문이 남을 가능성을 줄이기 위한 조치다.
- Dock/작업 표시줄 또는 `Cmd/Ctrl+Shift+H`로 복원하면 `1,200ms`
  보호 시간을 둔 뒤 다시 무장한다.
- 자동 복원은 하지 않는다. 복원은 항상 사용자의 명시적 조작이어야
  한다.

포커스 이탈은 사용자가 다른 앱으로 전환하는 상황에는 잘 대응하지만,
사람이 다가오기만 하고 포커스가 그대로인 상황을 감지하지는 못한다.
이 경우에는 기존 전역 즉시 접기 단축키가 가장 빠르고 예측 가능한
대응 수단이다.

## 5. 상태와 안전장치

### 세션 상태

```ts
type AutoFoldPhase =
  | "off"
  | "arming-grace"
  | "armed"
  | "suspended"
  | "folding"
  | "restore-grace";

interface StealthAutoFoldSession {
  armed: boolean;
  phase: AutoFoldPhase;
  generation: number;
  suspendCount: number;
}
```

- `armed`와 `phase`는 영속 저장하지 않는다.
- 사용자가 선호하는 유휴 시간 같은 후속 옵션만 나중에 별도 저장한다.
- 몰래보기 종료, 안전 복구, 새로고침, 앱 재시작 시 `off`로 돌아간다.
- 모바일 런타임에서는 상태와 UI를 생성하지 않는다.

### 접기 조건

다음 조건을 모두 만족할 때만 최소화한다.

- 데스크톱 Tauri 런타임
- 몰래보기 활성
- 자동 접기 무장
- `phase === "armed"`
- 네이티브 포커스 이탈 확인
- 이미 최소화 중이 아니고 중복 요청이 없음
- 네이티브 파일 선택기나 시스템 대화상자로 인해 일시 중지된 상태가
  아님
- 창 geometry 전환 또는 드래그 직후 보호 시간이 아님

### 반드시 막아야 하는 반복

- 최소화 자체가 다시 포커스 이탈 이벤트를 만들어 두 번째 최소화를
  호출하는 경우
- Dock 복원 직후 포커스 이벤트 순서가 엇갈려 즉시 다시 접히는 경우
- 몰래보기 진입 중 창 크기·위치를 바꾸는 과정에서 포커스가 흔들리는
  경우
- 빠르게 켜기/끄기를 반복했을 때 이전 타이머가 뒤늦게 실행되는 경우
- 네이티브 파일 선택기 뒤에 본창까지 접혀 대화상자만 남는 경우

`generation` 값과 단일 예약 타이머를 사용해 이전 세션의 콜백을
무효화하고, 접기 함수는 실행 중 여부를 검사하는 멱등 동작으로 만든다.

## 6. UI

### 빠른 상단 바

- 방패 또는 접힌 창 아이콘 하나를 추가한다.
- 접근성 이름:
  - 꺼짐: `포커스 이탈 자동 접기 켜기`
  - 켜짐: `포커스 이탈 자동 접기 끄기`
- `aria-pressed`와 색상·작은 상태점을 함께 사용한다.
- 켤 때 `다른 앱을 선택하면 이 창을 안전하게 접습니다` 토스트를 한
  번 표시한다.
- 자동 접기로 복원된 직후에는 `자동 접기로 안전하게 접혔습니다`
  안내를 한 번만 표시하고 중립 가림막을 제거한다.
- 기존 PC 기능 단순화 원칙을 지키기 위해 빠른 바에는 설정 팝오버나
  여러 모드 버튼을 추가하지 않는다.

### 화면 설정

`화면 설정`의 접힌 `몰래보기 자동 접기` 설명에는 다음만 둔다.

- 현재 세션 자동 접기 켜기/끄기
- `다른 앱으로 포커스가 이동하면 최소화됩니다`
- `앱을 다시 열면 자동으로 켜지지 않습니다`
- 전역 안전 접기 단축키 안내

유휴 시간 옵션은 1차 사용성 검증 후 필요할 때만
`끔 / 30초 / 1분 / 3분`으로 추가한다.

## 7. 구현 구조

### 프런트엔드

- `src/platform/desktopAutoFold.ts`
  - 테스트 가능한 자동 접기 컨트롤러와 포트 계약
- `src/platform/tauriDesktopAutoFoldPort.ts`
  - 네이티브 포커스 구독, 포커스·최소화 상태 확인, 안전 최소화
- `src/hooks/useDesktopAutoFold.ts`
  - 몰래보기·geometry·대화상자 억제 상태와 컨트롤러 수명 연결
- `src/core/autoFold.ts`
  - 부작용 없는 상태 전이와 접기 가능 여부
- `src/appStore.ts`
  - 영속화하지 않는 세션 무장 상태와 액션
- `src/App.tsx`
  - 몰래보기 수명주기에 맞춰 구독·해제
  - 빠른 바 버튼과 토스트
  - 수동·자동 접기가 공유하는 단일 `safelyMinimizeWindow(reason)`
- `src/styles.css`
  - 유동 이동 영역, 컨트롤 비드래그 영역, 무장 상태 표시

Tauri 2의 `getCurrentWindow().onFocusChanged()`와 기존 `minimize()`
경로로 1차 구현이 가능하다. 마지막 상태 재확인을 위해 capability에
`core:window:allow-is-focused`와 `core:window:allow-is-minimized`를
추가하되 Rust 플러그인이나 새 운영체제 개인정보 권한은 요구하지
않는다.

React StrictMode에서 비동기 focus listener 등록이 cleanup보다 늦게
끝나도 listener가 남지 않게, 등록 Promise가 해제 이후 resolve되면
반환된 unlisten을 즉시 호출한다. 절전·재개와
`document.visibilitychange` 복귀는 이전 idle/blur 타이머를 실행하는
신호가 아니라 새 활동과 재무장 신호로 취급한다.

### 후속 네이티브 범위

- 화면 잠금·세션 잠금 이벤트는 macOS와 Windows가 서로 달라 별도
  Rust 플랫폼 어댑터로 분리한다.
- 시스템 전체 마우스 모서리 제스처도 전역 입력 감시가 필요하므로
  사용성 승인 전에는 구현하지 않는다.

## 8. 구현 순서

### 1단계 — 상단 이동 영역

- 전체 툴바 배경을 deep drag region으로 전환
- 입력과 버튼을 명시적인 drag 차단 영역으로 설정
- 이동 핸들을 유동 폭으로 변경
- `430px`와 방어적 `360px` overflow·조작 영역 계약 테스트
- 브라우저 계약 테스트와 macOS 실제 좌표 이동 확인

### 2단계 — 순수 상태 모델

- 자동 접기 단계, 세대 토큰, 안정화·복원 보호 시간 구현
- 가짜 시계로 포커스 이탈/복귀/중복 이벤트 단위 테스트
- 몰래보기 종료와 새로고침 시 무장 해제 테스트

### 3단계 — 네이티브 포커스 연결

- Tauri `onFocusChanged()` 구독과 정리
- 수동 접기와 자동 접기의 최소화 경로 통합
- 네이티브 대화상자·geometry 전환·드래그 중 일시 중지
- 자동 접기 빠른 버튼과 상태 토스트 구현

### 4단계 — 승인

- macOS에서 다른 앱 클릭 → 최소화 → Dock/단축키 복원 반복 검증
- Windows에서 작업 표시줄 복원과 항상 위 조합 검증
- 반복 50회 동안 이중 최소화, 즉시 재접기, 창 위치 손실이 없는지 확인
- 실제 사용 후 유휴 시간 옵션의 필요성을 다시 결정

## 9. 자동 테스트

### 단위 테스트

- 기본 상태는 `off`
- 무장 후 포커스 이탈 299ms에는 접히지 않고 300ms에 한 번 접힘
- 300ms 안에 포커스가 돌아오면 취소
- 동일 포커스 이탈 이벤트 반복에도 최소화 한 번
- 복원 후 1,200ms 동안 재접기 금지
- 세대가 바뀐 이전 타이머 무효화
- 일시 중지 중 포커스 이탈 무시
- 몰래보기 종료·새로고침·모바일에서 무장 해제

### Playwright

- 상단 툴바와 이동 핸들은 `deep`
- 슬라이더·버튼은 `false`
- 상단 농도 슬라이더는 배경 alpha를 따라 희미해지고 hover·focus에서
  복구되며, 하단 독서 진행 바는 별도로 유지됨
- 본문을 드래그해도 선택문과 네이티브 드래그가 발생하지 않음
- 이동 영역 최소 크기와 `430px` overflow 없음
- 자동 접기 버튼의 이름, `aria-pressed`, 토스트
- 자동 접기 직전 중립 가림막과 복원 후 제거
- 가짜 네이티브 어댑터로 포커스 이탈 시 최소화 요청 한 번
- 모바일에는 자동 접기 버튼 없음

### 네이티브

- 드래그 가능 지점과 금지 지점 각각에서 이동 전후 창 좌표 비교
- 자동 접기 꺼짐 상태에서 다른 앱을 눌러도 최소화되지 않음
- 자동 접기 켜짐 상태에서 다른 앱을 누르면 지정 시간 안에 최소화
- Dock/작업 표시줄과 전역 단축키 복원 후 즉시 재접히지 않음
- 투명도 0%와 항상 위 상태에서도 같은 결과
- 최소화 직전과 작업 표시줄 미리보기에서 본문 대신 중립 가림막 표시

## 10. 완료 조건

- 사용자가 왼쪽 모서리를 정확히 겨냥하지 않아도 상단 빈 영역에서
  자연스럽게 창을 옮길 수 있다.
- 슬라이더와 모든 버튼 조작은 창 이동과 충돌하지 않는다.
- 자동 접기는 명시적으로 켠 몰래보기 세션에서만 동작한다.
- 어떤 자동 경로도 `hide()`를 호출하지 않으며 Dock/작업 표시줄과
  전역 단축키 복원이 항상 가능하다.
- 카메라·마이크·외부 서버·사용자 콘텐츠 로깅이 추가되지 않는다.
- macOS와 Windows 실제 환경 승인 전에는 자동 접기를 완료로 표시하지
  않는다.
