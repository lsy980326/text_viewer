# NOVELIER 프로젝트 계획

> 최종 갱신: 2026-07-26
> 제품명: **NOVELIER**
> 개발용 패키지 식별자: `app.novelier.reader`

## 1. 목표

NOVELIER는 사용자가 가진 TXT 소설을 서버 업로드 없이 읽는 설치형
리더다. React/TypeScript 기반의 공통 UI와 Tauri 2 네이티브 셸을 사용해
macOS, Windows, iOS, Android에서 같은 독서 경험을 제공한다.

핵심 원칙은 다음과 같다.

- 소설 본문과 독서 기록은 기기 안에서만 처리한다.
- 데스크톱과 모바일 모두 같은 기능 모델을 사용하되 각 플랫폼의 창,
  safe-area, 뒤로가기 관례를 따른다.
- 페이지 번호가 아닌 본문 위치를 저장해 창 크기나 글꼴이 바뀌어도 같은
  문장으로 돌아간다.
- 참고 이미지의 조용한 정보 위계, 넉넉한 여백, 긴 글에 적합한 타이포를
  제품 전반에 일관되게 적용한다.

세부 화면 규칙은 [UI 명세](./UI_SPEC.md), 실제 작업 이력은
[오케스트레이션 로그](./ORCHESTRATION_LOG.md)에서 관리한다.
몰래보기 상단 전체 이동 영역과 안전한 포커스 이탈 자동 접기의 후속
설계는 [몰래보기 상단 이동·자동 접기 계획](./STEALTH_AUTO_FOLD_PLAN.md)
에서 관리한다.

## 4. 기술 구조

### 애플리케이션 계층

1. **표현 계층**
   - `library | reader` 화면과 반응형 내비게이션을 담당한다.
   - 리더 상태는 `vertical-scroll | horizontal-paged` 읽기 방식과
     `library | jump | bookmarks | settings` 도구 선택을 사용한다.
   - 드로어, 팝오버, 바텀시트는 한 번에 하나만 열린다.
2. **리더 도메인**
   - 문단 블록, 누적 문자 위치, 페이지 계산, 검색, 글자 수, 위치 변환을
     UI 및 플랫폼 코드와 분리한다.
   - 페이지는 원문을 복제하지 않는 UTF-16 반열림 offset 범위만
     보관하며, Unicode grapheme와 문단 경계를 안전하게 지킨다.
   - `Intl.Segmenter`를 우선 사용해 Unicode 사용자 인식 문자 단위로
     글자 수를 계산하고, 미지원 환경에는 검증된 폴백을 둔다.
3. **저장소**
   - Tauri에서는 SQLite 트랜잭션으로 책, 본문 블록, 읽기 위치, 설정,
     북마크를 저장하고 웹 개발·Playwright에서는 같은 계약의
     IndexedDB 저장소를 사용한다.
   - 원본 TXT는 가져오기 시 읽고 앱 샌드박스에 필요한 데이터만
     보존한다. 원본 경로나 파일명은 로그에 기록하지 않는다.
4. **플랫폼 어댑터**
   - 파일 선택과 모바일 content URI 차이는 파일 선택 어댑터 안에
     캡슐화하고, 창 항상 위, Android 뒤로가기와 음량 키 이동은 Tauri
     런타임에서만 연결한다.
   - `PlatformCapabilities` 공통 타입은 정의되어 있으나 현재 UI 분기는
     런타임 플랫폼 표식과 뷰포트 규칙을 사용한다. capability 객체의
     직접 주입은 후속 구조 정리 범위다.

### 공통 데이터 계약

| 타입 | 필수 의미 |
| --- | --- |
| `BookRecord` | 내부 ID, 제목, 콘텐츠 해시, 바이트 크기, 생성/최근 읽은 시각, 읽기 진행률 |
| `ReadingLocator` | 본문 블록 ID, 블록 내 문자 오프셋, 주변 문맥 해시, 전체 진행 비율 |
| `ReaderSettings` | 읽기 방식, 타이포·여백, 테마, 밝기, 투명 모드·농도, 항상 위, 간단보기, 글자 수 공백 규칙, Android 음량 키 이동 선택 |
| `CharacterStats` | 공백 포함/제외 기준의 전체 및 현재 화면 글자 수 |
| `Bookmark` | 내부 ID, 책 ID, 위치, 미리보기용 짧은 문맥, 생성 시각 |
| `PlatformCapabilities` | 파일 선택, 실제 창 투명도, 항상 위, 모바일 표면과 Android 음량 키 지원 여부 |

페이지 번호는 영구 저장 식별자로 사용하지 않는다. `ReadingLocator`의
주변 문맥 해시는 본문을 로그에 노출하지 않고도 블록 분할 변경이나
오프셋 오차를 보정하는 데 사용한다.

### TXT 가져오기

1. 네이티브 파일 선택기에서 `.txt` 한 개를 선택한다.
2. 50MB를 초과하면 읽기 전에 중단하고 제한과 해결 방법을 알린다.
3. 바이트 해시를 계산해 이미 가져온 콘텐츠인지 확인한다.
4. BOM과 유효성 검사로 UTF-8/UTF-16을 판별하고, 한국어 레거시
   인코딩 후보를 검사한다.
5. 결과가 불확실하거나 대체 문자가 과도하면 UTF-8, CP949/EUC-KR,
   UTF-16 중 사용자가 직접 고르는 미리보기 화면을 연다.
6. 줄바꿈을 정규화하고 문단 단위 블록으로 나눈다. 매우 긴 문단은
   안전한 문자 경계에서 더 작게 나눈다.
7. 제목은 선택한 파일의 확장자를 제거한 값으로 생성한다. 저자, 장,
   목차 정보는 추론하지 않는다.
8. 책, 블록, 초기 위치를 하나의 트랜잭션으로 저장한다. 실패하면
   불완전한 책을 남기지 않는다.

### 읽기 위치와 페이지 계산

- 세로 모드는 위 10문단, 기준 문단, 아래 48문단으로 최대 59개 문단만
  마운트하고 위·아래 spacer로 전체 스크롤 높이를 유지한다. 3,000문단
  승인 fixture에서는 DOM 240개 이하라는 여유 있는 상한도 검증한다.
- 가로 모드는 현재 뷰포트와 설정을 기준으로 원문 offset 범위를
  결정하고 현재 범위만 렌더링한다. 범위에는 페이지 문자열을 보관하지
  않으며 offset 탐색은 이진 탐색으로 처리한다.
- 창 리사이즈, 회전, 글꼴·행간·본문 폭 변경 전 현재
  `ReadingLocator`를 캡처하고 재배치가 끝난 뒤 복원한다.
- 재계산 중에는 예전 전체 페이지 수를 새 레이아웃의 값처럼 표시하지
  않고 `페이지 계산 중…` 상태를 표시하며 직접 페이지 입력을 잠근다.
- 첫 가시 문단 기준 ±1문단 복원은 가로↔세로 왕복과 집중 모드 복귀
  Playwright 승인 테스트로 고정한다.
- 50MiB 형태의 단일 장문 문단도 offset 인덱싱과 레이아웃 계산을
  5초 가드 안에서 처리하는 단위 테스트를 유지한다.

## 5. 플랫폼 동작

### 데스크톱

- 기본 창 `1280×900`, 최소 창 `720×560`
- 간단보기는 내비게이션과 문맥 패널을 접어 리더를 전체 폭으로
  확장하며 재실행 후에도 설정을 복원한다.
- macOS·Windows 모두 장식 없는 사용자 지정 타이틀바를 사용한다.
- 투명 가능한 창에서 단일 배경 표면 alpha만 0~100%로 조절하고,
  투명 모드에서는 외곽선·네이티브 그림자·프레임 블러도 제거한다.
- 일반 PC의 투명 모드와 항상 위 기본값 꺼짐, 투명 모드의 초기 배경
  농도 82%. 몰래보기에서는 항상 위를 자동 적용
- 글자와 아이콘은 투명도 설정과 무관하게 불투명 유지
- 데스크톱 전용 `몰래보기` 버튼은 현재 창 geometry를 저장하고
  `430×760` 모바일형 한 열 미니 창으로 전환한다.
- 몰래보기는 저장된 일반 설정을 덮어쓰지 않는 세션 상태다. 진입 시
  배경 농도 28%, 간단보기와 항상 위를 자동 적용한다. 상단 농도
  슬라이더와 퍼센트도 현재 배경 alpha에 맞춰 희미해지고, hover·focus
  시 충분히 드러나 즉시 다시 조절할 수 있다.
- 미니 창에는 복구 가능한 `창 안전하게 접기`와 일반 PC 창 복원
  조작을 항상 접근 가능하게 둔다. 새로고침으로 세션이 끝나도 저장한
  창 크기·위치·최대화 상태를 복구한다.
- 소설 본문은 브라우저 선택과 선택문 네이티브 드래그를 차단하되
  스크롤·페이지 스와이프와 접근성 텍스트 구조를 유지한다. 일반
  PC·모바일 중앙 탭은 보이는 chrome을 숨기기만 한다. 본문 좌·우
  클릭은 이전·다음 읽기 단위로 이동하며 중앙·좌·우 어느 탭도 숨긴
  chrome을 다시 열지 않는다. 숨긴 chrome은 실제 상·하단 UI가
  차지하던 영역 클릭으로만 다시 표시한다. 데스크톱 몰래보기에서는
  최상단 빠른 설정도 같은 숨김 대상에 포함한다.
- `Cmd/Ctrl+Shift+M`: 몰래보기 미니 창 진입·일반 PC 창 복원
- `Cmd/Ctrl+Shift+H`: 앱 포커스와 무관하게 창 안전 접기·복구
- `Cmd/Ctrl+Shift+S`: 간단보기와 기본 보기 전환
- `Cmd/Ctrl+Shift+T`: 데스크톱 투명 모드 전환
- `Cmd/Ctrl+Shift+0`: 몰래보기를 해제하고 저장한 일반
  PC 창 geometry 및 불투명 기본 표시로 안전 복구
- 네이티브 최소 창 `720×560`에서는 데스크톱 타이틀바를 유지하고
  도구를 320px 문맥 드로어로 열며 모바일 하단 툴바는 표시하지 않는다.
- Windows와 macOS 모두 드래그 가능한 사용자 지정 창 버튼 유지
- 최대화 시 외곽 반경과 그림자 제거

macOS의 완전 투명 창은 private API 제약이 있으므로 v1은 직접
개발·테스트 배포를 기준으로 하며 Mac App Store 호환을 완료 조건으로
삼지 않는다.

### 모바일

- 시스템 상태바와 홈 인디케이터를 다시 그리지 않고 safe-area를 사용
- 다른 앱이 비치는 투명 창 대신 툴바·시트의 반투명 재질과 본문 디밍 제공
- iOS·Android에는 데스크톱 몰래보기 버튼, 창 geometry 조작, 전용
  단축키와 항상 위 프리셋을 노출하지 않는다.
- Android 뒤로가기 우선순위: 열린 시트/메뉴 닫기 → 리더에서 서재로 이동
  → 시스템에 뒤로가기 전달
- Android의 `음량 버튼으로 페이지 넘기기`는 한 번의 설정
  마이그레이션에서 기본값을 켜며 사용자가 끈 값은 보존한다. 활성
  리더에서만 음량 올림은 이전, 음량 내림은 다음
  읽기 구간으로 이동한다. 서재·열린 시트·백그라운드에서는 키를
  캡처하지 않아 시스템 음량 동작을 유지한다.
- iOS는 물리 음량 키를 페이지 키로 제공하는 공개 이벤트 API가 없고
  시스템 음량 관찰·재설정 우회는 실제 음량과 App Store 정책을
  침해하므로 제공하지 않는다. 화면 탭·스와이프와 외장 키보드 이동은
  계속 지원한다.
- 세로/가로 회전을 지원하되 휴대폰 가로에서도 본문은 한 열 유지

## 6. 구현 단계와 완료 조건

### 1단계 — 기반과 문서 · 완료

- 계획, UI 명세, 로그, 에이전트 규칙 작성
- React/TypeScript/Vite/Tauri 기본 프로젝트와 공통 품질 명령 구성
- **완료 조건:** 설치와 기본 빌드가 재현되고 문서와 로그가 실제 상태를
  반영한다.

### 2단계 — 반응형 시각 셸 · 완료

- 실제 데이터 없이 데스크톱 3단/2단/드로어 레이아웃과 모바일 리더 구현
- 공통 토큰, 아이콘, 테마, 포커스·오류·빈 상태 구현
- 기준 화면 스냅샷 생성
- **완료 조건:** 지정 해상도 스냅샷과 두 참고 이미지의 수동 비교를
  통과한다.

### 3단계 — 플랫폼과 로컬 데이터 · 완료

- Tauri 네 플랫폼 셸과 플랫폼 어댑터 구현
- TXT 가져오기, 인코딩 선택, 분할, 해시 중복 감지 구현
- SQLite 마이그레이션, 서재, 생성 표지, 삭제와 재실행 복원 구현
- **완료 조건:** 지원 인코딩과 경계 파일 테스트 및 영속성 테스트를
  통과한다.

### 4단계 — 읽기 엔진 · 완료

- 가로 페이지, 세로 가상 스크롤, 위치 저장·복원 구현
- 페이지/퍼센트 이동과 Unicode 글자 수 구현
- **현재 근거:** 가로↔세로 왕복과 집중 모드 복귀 ±1문단, 3,000문단
  DOM 상한과 50MiB 형태 엔진 성능 가드를 통과했다. 회전·전체 타이포
  조합은 확장 승인에 남긴다.

### 5단계 — 완성 기능 · 구현 완료, 네이티브 접근성 승인 대기

- 검색, 북마크, 설정, 집중 모드, 단축키 구현
- 데스크톱 투명 창·항상 위와 모바일 반투명 UI 구현
- 키보드 및 스크린리더 접근성 보완
- **현재 근거:** 공통 사용자 흐름과 키보드 dialog 포커스 계약을
  통과했다. VoiceOver·TalkBack과 실제 OS 창 동작은 수동 승인에 남긴다.

### 6단계 — 패키징 · 플랫폼별 네이티브 승인 대기

- 최신 본문 드래그 차단·투명도 연동 UI 소스로 macOS arm64 개발 앱
  재빌드·ad-hoc 서명·기동 완료
- 이전 승인 소스의 Windows x64 unsigned NSIS는 보존하되 다음 배포
  후보에서 최신 소스로 다시 생성
- Android 0.1.7 arm64 release APK는 현재·안정
  navigation/tappable/mandatory gesture inset, 영구 48px 보호값과
  추가 12px 여유를 적용해 가로 페이지 진행 정보, 하단 도구와
  chrome을 숨긴 소설 본문 뷰포트를 다시 배치했다. 가로 회전에서는
  같은 보호를 좌우 양쪽에 적용한다.
  가로 페이지가 렌더링된 뒤 각 실제 줄의 하단을 확인하고 본문 경계에
  걸치는 줄이 하나라도 있으면 페이지 용량을 줄여 해당 줄
  전체를 다음 페이지로 이동한다. UI 표시·숨김, 글꼴 로드, 창 크기와
  글꼴 설정 변경마다 같은 검사를 다시 수행한다.
  Android 16 Pixel 7 arm64 에뮬레이터에 실제 설치해 세로 제스처,
  세로 3버튼, 양방향 가로 3버튼과 가로 제스처 화면을 캡처·검증했다.
  세로 3버튼에서는 상·하단 UI를 숨긴 가로 페이지와 세로 스크롤을
  각각 캡처해 마지막 본문 행이 시스템 내비게이션 위에서 잘리는지
  확인했다.
  실제 제목 조회·다크 시스템 바·음량 키와 provider TXT 가져오기를
  유지하며 v2/v3 서명과 16KiB 정렬을 검증했고 제조사 실기기 승인을
  남김
- macOS 개발 앱 기동과 실제 최소화·Dock 복원 완료
- Windows 설치·투명 창과 Android 제스처·뒤로가기는 대상 OS/실기기
  수동 승인에 남김
- iOS 생성 프로젝트와 Rust 타깃 준비 완료; 전체 Xcode, iOS SDK와
  Simulator runtime이 설치되면 unsigned Simulator 빌드 수행
- **완료 조건:** 지원 OS의 실제 기기 또는 승인된 테스트 환경에서
  설치·실행·오프라인 복원을 확인한다.

## 7. 개발 산출물

최신 소스의 macOS 개발 앱은
`src-tauri/target/debug/bundle/macos/NOVELIER.app`에 생성했다. 기동,
ad-hoc 서명과 엄격 번들 검증을 완료했다.

Windows NSIS는 이전 승인 소스에서 만든 개발 산출물이다. 현재 릴리스
후보로 표시하지 않으며 최신 소스로 재빌드한 뒤 새 해시와 대상 OS
결과를 로그에 기록한다. Android APK는 최신 소스로 다시 만들었지만
실기기 입력 승인이 끝날 때까지 개발 산출물로만 취급한다. iOS 생성
프로젝트는 유지하지만 전체
Xcode·SDK·Simulator runtime 부재로 실행 빌드는 계속 차단되어 있다.

## 8. 테스트 및 승인 기준

### 자동화

- Vitest 60개 / 12개 파일: 파서, 인코딩, 블록 분할, Unicode 글자 수,
  locator, offset 페이지, 59문단 가상 창, 0% 투명도와 데스크톱 네이티브
  구성 계약, 50MiB 형태 성능 가드
- Rust/Tauri 정적 확인: `cargo fmt --check`, `cargo check`,
  capability·플러그인 구성과 SQLite migration 포함 여부
- Playwright 84개: 여섯 프로젝트에서 46개 실행 통과, 프로젝트 범위가
  맞지 않는 38개는 의도적으로 skip
- Playwright 승인: 가져오기, 페이지 이동, 검색, 북마크, 간단보기,
  투명 모드, 집중 모드, 몰래보기 `430×720` 자동 모바일형 레이아웃,
  가로↔세로 위치, 대용량 DOM 상한, 다이얼로그 포커스 복원과
  네이티브 `720×560` 좁은 창 계약
- 시각 회귀: `1280×900`, `1024×768`, `800×600`, `390×844`,
  `430×932`, 데스크톱 몰래보기 자동 `430×720`, 높이 520px 이하의
  휴대폰 가로 화면. 네이티브 몰래보기 창 `430×760`은 수동 검증

### 현재 자동 승인

- UTF-8/BOM, CP949·EUC-KR, UTF-16 LE/BE, CRLF/NFC 정규화, 빈 파일,
  Unicode grapheme와 50MB 초과 사전 거부
- 중복 콘텐츠, 문단 분할, 메모리 구현 기반 저장소·persistence 변환
  계약, 책 삭제 cascade와 locator 복원
- 가로↔세로 왕복과 집중 모드 복귀 후 첫 가시 문단 ±1문단
- 3,000문단 이동 전후 DOM 상한과 `720×560` 데스크톱 드로어·간단보기
- 검색, 페이지 이동, 북마크, 테마·투명 모드와 다이얼로그 포커스 복원

### 남은 확장·네이티브 승인

- 손상 파일의 인코딩 선택 전체 흐름과 저장 트랜잭션 실패 주입
- 실제 IndexedDB와 Tauri SQLite migration·rollback 통합
- 일반 창 리사이즈·회전·모든 타이포 조합 후 locator ±1문단
- 프로세스 종료·재실행 후 책, 설정, 위치, 북마크의 네이티브 복원

## 9. 기록과 상태 관리

- 모든 작업은 변경 전 `STARTED`, 보고 전 같은 작업 ID의 `COMPLETED`
  또는 `BLOCKED` 기록을 [오케스트레이션 로그](./ORCHESTRATION_LOG.md)에
  추가한다.
- 로그는 append-only이며 본문, 가져온 파일명, 비밀값, 내부 추론을
  포함하지 않는다.
- 단계가 완료됐다는 표시는 실행한 명령, 테스트 결과, 산출물 경로 등
  재현 가능한 근거가 있을 때만 갱신한다.
